## 1. ما هي زيرون؟

زيرون مشروع لغة برمجة وأدوات عربية تهدف إلى توفير طريقة ممتعة ومفهومة لكتابة البرامج، مع هوية سعودية في صياغة الأوامر. الرؤية البعيدة بناء منظومة تشمل لغة ومترجماً ومحرك تنفيذ ومكتبات وأدوات تطوير مستقلة، تدعم الألعاب والتطبيقات والأنظمة والذكاء الاصطناعي.

النموذج الموجود الآن يملك **قواعد نحوية وتحليلاً وتنفيذاً خاصاً به**، ولا يحوّل الأمر إلى صياغة بايثون ولا يعتمد على بايثون. لكنه مكتوب بلغة JavaScript ويعمل على محرك المتصفح أو Android WebView؛ لذلك ليس بعد مترجماً أصلياً مستقلاً عن بيئة تشغيل أخرى. تشابه بعض المفاهيم العامة مثل المتغيرات والدوال أو الرموز `+` و`{}` مع لغات أخرى طبيعي، ولا يعني أن زيرون نسخة من بايثون.

القوة لا تأتي من تعقيد القواعد أو صعوبتها بلا داعٍ؛ بل من دقة التصميم، وسلامة التنفيذ، والأداء المقاس، والتوافق، والاختبارات، والتوثيق، والمكتبات والأدوات. لا توجد بعد قياسات تثبت أن زيرون من أقوى لغات العالم.

## جديد 0.3: شاشة تشغيل وأساس ألعاب 2D

زر «تشغيل الكود» يفتح مساحة تشغيل مستقلة بدلاً من الاكتفاء بالمخرجات أسفل المحرر. على Android يطلب التطبيق اتجاه العرض الأفقي عند فتح مساحة اللعب ويعيد الوضع السابق عند العودة؛ سلوك الجهاز وتفضيلاته قد يؤثران في الدوران. في المتصفح يمكن لف الجهاز أو استخدام ملء الشاشة، ولا يضمن المتصفح قفل الاتجاه. زر العودة يوقف الحلقة ويعيدك للمحرر، وزر «إعادة» يشغّل الكود من البداية.

تضم النسخة واجهة رسم 2D محدودة ولوحة مفاتيح وأزرار لمس وتصادم مستطيلات ومثال «صيد النجوم» قابل للعب مع حارس يلاحق اللاعب بسلوك مبرمج بسيط، لا بنموذج تعلم آلي. لا تساوي محرك ألعاب احترافياً ولا تدعم 3D أو أصول الصور أو الصوت أو فيزياء متقدمة. أكواد 0.2 النصية تستمر بالعمل وتظهر مخرجاتها في شاشة التشغيل؛ زر «المخرجات» يظهر النص أثناء اللعب. الكود المحفوظ في 0.2 يستخدم نفس التخزين. زر «مثال لعبة» يستبدل الكود الحالي بعد التأكيد.

### كيف تعمل اللعبة؟

```zyr
خل س يكون ٤٨٠؛
خلفية("#10162d")؛
سالفة حدث(زمن) {
  لو مضغوط("يمين") { س يصير س + ٢٥٠ * زمن؛ }
}
سالفة ارسم() {
  دائرة(س، ٢٧٠، ٢٠، "#a78bfa")؛
}
وقت_التحديث(حدث)؛
وقت_الرسم(ارسم)؛
```

مساحة الرسم المنطقية 960 × 540، والنقطة (0، 0) أعلى اليسار. `وقت_التحديث` تستقبل اسم سالفة بمعامل واحد هو الزمن بالثواني منذ الإطار السابق (محدود بحد أقصى 0.05 ثانية)، و`وقت_الرسم` تستقبل اسم سالفة دون معاملات. ينفذ التحديث ثم تنظف الشاشة بلون الخلفية ثم ينفذ الرسم في كل إطار. الدوال المدمجة:

| السالفة المدمجة | المعاملات والسلوك |
|---|---|
| `خلفية(لون)` | لون خلفية سداسي مثل `"#10162d"`. |
| `مستطيل(س، ص، عرض، ارتفاع، لون)` | مستطيل ممتلئ؛ الأبعاد غير سالبة. |
| `دائرة(س، ص، نصف_القطر، لون)` | دائرة ممتلئة؛ نصف القطر غير سالب. |
| `اكتب_على_الشاشة(قيمة، س، ص، حجم، لون)` | رسم نص أو عدد؛ الحجم من 1 إلى 200، بمحاذاة يمين. |
| `مضغوط(اسم)` | `صح` عند ضغط `"يمين"` أو `"يسار"` أو `"فوق"` أو `"تحت"`. أسهم لوحة المفاتيح وWASD مدعومة كذلك. |
| `يتلامس(س١، ص١، عرض١، ارتفاع١، س٢، ص٢، عرض٢، ارتفاع٢)` | فحص تداخل مستطيلين؛ الأبعاد غير سالبة. |
| `عشوائي(أدنى، أعلى)` | عدد صحيح شامل الحدين؛ الحد الأدنى لا يتجاوز الأعلى. |
| `وقت_التحديث(اسم_سالفة)` | تسجيل سالفة التحديث ذات معامل واحد. |
| `وقت_الرسم(اسم_سالفة)` | تسجيل سالفة الرسم دون معاملات. |

الألوان تقبل `#` وست خانات سداسية فقط. الأعداد الهندسية يجب أن تكون منتهية وفي حدود مليون. توقف أخطاء التنفيذ حلقة اللعبة وتظهر في المخرجات، وتوجد ميزانية خطوات مشتركة لكل إطار؛ لا يعتبر ذلك عزلاً أمنياً كاملاً. مثال اللعبة الكامل موجود في `examples/صيد-النجوم.zyr` ويمكن تحميله من زر المثال في المحرر. أساس 2D يستخدم Canvas داخل WebView ولا ينتج APK مستقلاً للعبة.

## 2. ما الجديد في 0.2؟

أُعيد تصميم القواعد لتصبح صياغتها ذات هوية مختلفة، بدلاً من الاكتفاء بتغيير أسماء أوامر إنجليزية:

```zyr
خل الاسم يكون "زيرون"؛
ورني "يا هلا في"، الاسم؛

لف ٣ مرات {
  ورني "هذي اللفة رقم"، الجولة؛
}
```

- إنشاء المتغير: `خل الاسم يكون القيمة؛`؛ وتحديثه: `الاسم يصير القيمة؛`.
- عرض المخرجات: `ورني القيمة؛` دون استدعاء دالة `print` أو `اطبع`.
- قرار: `لو شرط { ... } غير كذا { ... }` دون اشتراط أقواس حول الشرط.
- تكرار بعدد: `لف عدد مرات { ... }` مع متغير محلي اسمه `الجولة` يبدأ من واحد.
- تكرار مشروط: `دام شرط { ... }`.
- تعريف وظيفة: `سالفة اسم(معامل) { رجع قيمة؛ }`.
- معاملات كلامية: `يساوي` و`أكبر من` و`أقل من` و`و` و`أو` و`مو`.
- أخطاء ومفردات مستوحاة من الكلام السعودي. استخدام اللهجات يختلف بين أهل المملكة، وهذه صياغة تصميمية وليست ادعاءً بتمثيل كل اللهجات.

هذا تغيير كاسر للتوافق: برامج 0.1 لا تعمل تلقائياً بقواعد 0.2. لم تُضف صياغات بايثون أو الأوامر الإنجليزية كبديل في 0.2، رغم أن دعم الإنجليزية كان ضمن رؤية المشروع البعيدة ويمكن تصميمه لاحقاً دون فرضه على الصياغة السعودية.

## 3. ما الذي يعمل اليوم وما الذي لم يُبنَ؟

### يعمل في النسخة التجريبية

- محرر يعمل في المتصفح وتطبيق أندرويد مع خلفية للكود وأرقام للأسطر وأمثلة ومساحة تشغيل مستقلة، وأساس لرسم ألعاب 2D.
- تخزين آخر كود للنسخة الجديدة محلياً قدر الإمكان؛ لا يعد ذلك نسخة احتياطية.
- محلل رموز ومحلل نحو ومفسر لقواعد 0.2، دون `eval` أو تشغيل المصدر كشيفرة JavaScript.
- أعداد ونصوص ومنطق وقيمة فارغة ومتغيرات، وحساب ومقارنة، وقرار وتكرار وسوالف.
- تكرار محدد مع `الجولة`، وتعليقات، ورسائل أخطاء، وحد لخطوات التنفيذ.
- تشغيل محلي للأمثلة الأساسية دون الحاجة إلى خادم ذكاء اصطناعي أو اتصال إنترنت داخل التطبيق.

### غير موجود أو لم يكتمل

لا يوجد بعد مترجم أصلي ينتج برامج مستقلة أو يصدر مشاريع زيرون إلى APK، ولا محرك ألعاب متكامل أو فيزياء متقدمة أو رسومات ثلاثية الأبعاد، ولا تدريب ذكاء اصطناعي أو GPU، ولا قوائم ومصفوفات وقواميس وأصناف، ولا نظام ملفات أو شبكة أو قاعدة بيانات أو حزم أو صلاحيات أو مهام متزامنة. لا يوجد مصحح أخطاء أو إكمال تلقائي أو استيراد وحفظ لملفات `.zyr` من واجهة المحرر. هذه أهداف مستقبلية لا ينبغي وصفها بأنها تعمل الآن.

## 4. تثبيت تطبيق أندرويد واستخدامه

1. حمّل `zayron-studio-0.3-debug.apk` من صفحة التحميل الموثوقة للمشروع.
2. افتح الملف من تطبيق التنزيلات على جهاز أندرويد 6.0 أو أحدث. قد يطلب النظام السماح لتطبيق الملفات بتثبيت تطبيقات من هذا المصدر.
3. افتح «زيرون ستوديو»، اكتب الكود في المحرر واضغط **تشغيل الكود**؛ تفتح مساحة اللعب أو المخرجات بشكل مستقل.
4. أمثلة البداية قابلة للتحميل إلى المحرر بعد تأكيد استبدال الكود الموجود.

التطبيق موقّع بمفتاح تجريبي عام، وليس مفتاح إصدار إنتاجي. لم يُختبر على جميع الأجهزة أو حتى على جهاز حقيقي في بيئة البناء الحالية. بعض إصدارات Android أو Play Protect قد تعرض تحذيراً؛ لا تثبت الملف إلا إذا كنت تثق بمصدره. يحتاج الجهاز Android System WebView صالحاً وحديثاً بما يكفي لدعم JavaScript الحديث.

إذا كان لديك التطبيق 0.1 أو 0.2 المثبت من هذا المشروع، فإن 0.3 يحمل رقم إصدار أعلى ويستخدم توقيع البناء التجريبي نفسه عند بنائه بالطريقة المرفقة؛ ومع ذلك قد يفشل التحديث إذا كان توقيع نسختك السابقة مختلفاً. إزالة التطبيق قد تحذف بياناته؛ انسخ كودك قبل أي إزالة. عند توفر كود قديم مخزن محلياً يظهر زر **استرجع كود 0.1**، ويضعه في المحرر لتعديله يدوياً. الزر يستبدل الكود الحالي بعد التأكيد، ولا يحوّل الصياغة تلقائياً. إن لم يظهر الزر أو سبق مسح بيانات التطبيق فلن يستعيد نسخة غير موجودة.

## 5. تشغيل زيرون على المتصفح

من جذر المشروع:

```sh
python3 -m http.server 8000 --bind 0.0.0.0
```

افتح عنوان الخادم من المتصفح. على جهاز مختلف استخدم عنوان الخادم الذي يمكن لذلك الجهاز الوصول إليه، لا `localhost` الخاص بالجهاز الآخر. اضغط تشغيل لمشاهدة المخرجات. الإنترنت غير مطلوب لتنفيذ الكود بعد تحميل الملفات المحلية؛ الموقع المستضاف يحتاج اتصالاً لتحميلها بدايةً. لفحص المفسر آلياً:

```sh
node tests/engine.test.js
```

### بناء التطبيق من المصدر

افتح `android` في Android Studio، مع JDK 17 وAndroid SDK 35 وGradle 8.9، أو شغل `gradle -p android assembleDebug` من جذر المشروع بعد إعداد الأدوات. المخرج المعتاد `android/app/build/outputs/apk/debug/app-debug.apk`. يضم المشروع مهمة GitHub Actions تبني ملف debug عند تشغيلها على مستودع مرفوع ومفعّل فيه Actions. مفتاح debug الذي ينشئه جهاز أو CI قد يختلف عن مفتاح الملف المرفق؛ لذلك لا تضمن نسخ البناء المختلفة إمكانية التحديث فوق بعضها. إصدار الإنتاج يحتاج مفتاحاً خاصاً وسياسة توزيع آمنة منفصلة.

## 6. أول برنامج

```zyr
// أول خطوة مع زيرون
ورني "يا هلا بالعالم!"؛
```

اكتب المثال في المحرر واضغط تشغيل. ستظهر العبارة في المخرجات. `ورني` تعليمة لغة، وليست دالة مطبوعة بصيغة `print(...)`. تكتب بعدها قيمة أو أكثر، تفصل بينها بالفاصلة العربية `،` أو الإنجليزية `,`؛ تُعرض القيم مفصولة بمسافة.

```zyr
ورني "يا هلا"، "يا مبرمج"، ٢٠٢٦؛
```

يمكن كتابة `ورّني` بالشدة أو `ورني` بدونها. يزيل المحلل الحركات العربية عند التعرف على الكلمات المحجوزة فقط؛ أسماء المستخدمين تحتفظ بشكلها الدقيق، فحافظ على طريقة كتابة الاسم في كل مرة.

## 7. قواعد كتابة البرامج

- التعليمات البسيطة تنتهي بفاصلة منقوطة عربية `؛` أو إنجليزية `;`، بما فيها `خل` و`يصير` و`ورني` و`رجع` واستدعاء سالفة كتعليمة.
- مجموعات التعليمات توضع بين `{` و`}`. لا تحتاج فاصلة منقوطة بعد نهاية مجموعة `لو` أو `دام` أو `لف` أو تعريف `سالفة`.
- `//` أو `#` يبدأ تعليقاً حتى نهاية السطر.
- النص بين `"` و`"` أو بين `'` و`'`. يمكن استخدام `\n` لسطر جديد و`\t` لجدولة داخل النص.
- يقبل المحلل الأرقام العربية ٠–٩ والإنجليزية 0–9، ويستخدم النقطة الإنجليزية للكسور مثل `٣.٥`.
- أسماء المتغيرات تبدأ بحرف أو `_`، ثم تقبل حروفاً وأرقاماً و`_`. الكلمات المحجوزة في جدول المرجع لا تصلح أسماء للمتغيرات.
- الصياغة لا تعتمد على مسافات بادئة مثل بايثون؛ ننصح بتنظيم المسافات لسهولة القراءة، لكن الأقواس المعقوفة هي التي تحدد الكتل.

## 8. أنواع القيم والمتغيرات

### المتغيرات

```zyr
خل الاسم يكون "نورة"؛
خل الرصيد يكون ١٠؛
الرصيد يصير الرصيد + ٥؛
ورني الاسم، الرصيد؛
```

`خل` يعرّف الاسم في نطاقه الحالي. `يصير` يغير قيمة اسم موجود في أقرب نطاق ظاهر. لا يمكن تعريف الاسم مرتين في النطاق نفسه، ولا تغييره قبل تعريفه. القيم غير مرتبطة بنوع ثابت في هذه النسخة، ويمكن إسناد قيمة من نوع آخر لاحقاً.

### القيم المتوفرة

| النوع | أمثلة | ملاحظات |
|---|---|---|
| عدد | `١٢`، `3.5`، `-٢` | أعداد JavaScript في التطبيق، وليست أنواعاً مستقلة للعدد الصحيح والعشري |
| نص | `"زيرون"`، `'يا هلا'` | الجمع بين نصين ممكن |
| منطقي | `صح`، `غلط` | ناتج المقارنات والعمليات المنطقية |
| فارغ | `فاضي` | قيمة غياب النتيجة |
| سالفة | تعريف بـ `سالفة` | يمكن استدعاؤها بالاسم |

الأعداد تخضع لدقة أعداد JavaScript وحدودها. أنواع الأحرف والقوائم والقواميس والمصفوفات والكائنات لم تُنفذ، وكتابة أقواس لها لن تجعلها مدعومة.

## 9. الحساب والمقارنة والمنطق

### الحساب

`+` للجمع، `-` للطرح، `*` للضرب، `/` للقسمة و`%` لباقي القسمة. الجمع يقبل عددين أو نصين؛ لا يجمع نصاً مع عدد ضمنياً. تمرير قيم متعددة إلى `ورني` يغني عن جمع النص والعدد. الضرب والقسمة أسبق من الجمع والطرح. استخدم الأقواس لضبط الأولوية.

```zyr
خل السعر يكون ١٥؛
خل العدد يكون ٣؛
ورني "المجموع:"، السعر * العدد؛
ورني (السعر + ٥) * العدد؛
```

القسمة أو الباقي على صفر خطأ.

### المقارنة

```zyr
ورني ٥ يساوي ٥؛
ورني ٨ أكبر من ٥؛
ورني ٢ أقل من ٣؛
ورني ٣ != ٤؛
ورني ٣ <= ٣؛
ورني ٤ >= ٣؛
```

يمكن أيضاً استخدام `==` و`<` و`>`. المساواة `يساوي` و`==` صارمة؛ لا تحول الأنواع تلقائياً. المقارنات الترتيبية في هذه النسخة تستخدم قواعد مقارنة JavaScript، لذا ينصح بمقارنة قيمتين من النوع نفسه. لا توجد حالياً صياغة كلامية لـ«أكبر من أو يساوي»؛ استخدم `>=`.

### المنطق

`و` و`أو` و`مو` تربط أو تعكس الشروط. تقيّم `و` و`أو` الطرف الثاني عند الحاجة فقط؛ القيمة الناتجة من العمليات المنطقية هي `صح` أو `غلط`. تستخدم الشروط قواعد الصدق في JavaScript في هذا النموذج، لذا يفضل التعبير المقارن أو القيم المنطقية الصريحة بدلاً من الاعتماد على تحويل النصوص والأعداد.

```zyr
خل العمر يكون ٢٠؛
خل مسجل يكون صح؛
ورني العمر أكبر من ١٧ و مسجل؛
ورني مو غلط؛
```

## 10. القرارات: لو وغير كذا

```zyr
خل الدرجة يكون ٨٠؛
لو الدرجة >= ٦٠ {
  ورني "كفو، نجحت!"؛
} غير كذا {
  ورني "حاول مرة ثانية"؛
}
```

يمكن حذف `غير كذا` إذا لم تحتج فرعاً آخر. يمكن استخدام الأقواس حول الشرط اختيارياً، لكن ليست مطلوبة. لا توجد صياغة مستقلة لـ«وإلا لو» بعد؛ يمكن وضع `لو` داخل مجموعة `غير كذا`.

## 11. التكرار: لف ودام

### عدد محدد مع الجولة

```zyr
لف ٣ مرات {
  ورني "هذي اللفة"، الجولة؛
}
```

الناتج هو ثلاث رسائل بأرقام 1 و2 و3. يُحسب تعبير العدد **مرة واحدة قبل بدء اللفات**، ويجب أن يكون عدداً صحيحاً آمناً غير سالب؛ صفر يعني عدم تنفيذ المجموعة. لكل لفة نطاق محلي جديد يحتوي على `الجولة` من 1 إلى العدد. لا توجد `الجولة` خارج الحلقة إلا إذا عرّفت اسماً مستقلاً بنفسك. عند تداخل حلقتين، تشير `الجولة` داخل الحلقة الداخلية إلى رقم الداخلية، وتعود للخارجية عند انتهائها.

```zyr
خل العدد يكون ٢؛
لف العدد مرات {
  العدد يصير العدد + ١؛
  ورني الجولة؛
}
ورني العدد؛ // ٤، رغم تغيير العدد لم يتغير عدد اللفات
```

### طالما تحقق الشرط

```zyr
خل رقم يكون ١؛
دام رقم <= ٣ {
  ورني رقم؛
  رقم يصير رقم + ١؛
}
```

يُعاد تقييم شرط `دام` قبل كل لفة. احرص أن يصل الشرط إلى قيمة غير محققة وإلا يتدخل حد خطوات التنفيذ. لا تدعم النسخة حالياً تعليمة خروج مبكر من الحلقة أو تخطي لفة؛ يمكن استخدام `رجع` داخل سالفة لإرجاع قيمة وإنهاء تنفيذ السالفة.

## 12. السوالف: تعريف عمليات قابلة لإعادة الاستخدام

```zyr
سالفة ضاعف(عدد) {
  رجع عدد * ٢؛
}
ورني ضاعف(٥)؛
```

`سالفة` تعرّف عملية باسم ومعاملات بين أقواس. `رجع` تعيد نتيجة داخل سالفة فقط. إن لم تنفذ `رجع` فالنتيجة `فاضي`. يجب تمرير عدد المعاملات المطابق تماماً. تستطيع السالفة استدعاء نفسها ضمن حد عمق التنفيذ. كل استدعاء ينشئ نطاقه الخاص، وتستطيع السالفة الوصول إلى الأسماء في النطاق المحيط بتعريفها.

```zyr
سالفة الأكبر(أ، ب) {
  لو أ أكبر من ب { رجع أ؛ }
  رجع ب؛
}
ورني الأكبر(٧، ١٢)؛
```

## 13. النطاقات وحياة الأسماء

- النطاق العام يحتفظ بالأسماء المعرّفة خارج الكتل.
- كل مجموعة `لو` أو `غير كذا` وكل لفة تكرار تنفذ في نطاق فرعي جديد.
- الاسم المعرّف في نطاق داخلي لا يظهر بعد انتهاء ذلك النطاق.
- يمكن للنطاق الداخلي قراءة اسم خارجي وتغييره بـ `يصير`، ويمكنه تعريف اسم محلي جديد له الاسم نفسه فيحجب الاسم الخارجي داخل النطاق.
- السوالف تحتفظ بالنطاق المحيط بتعريفها. تستخدم الأسماء وفق كتابتها الدقيقة، بما في ذلك التشكيل في أسماء المستخدمين.

مثال:

```zyr
خل الاسم يكون "الأصل"؛
لو صح {
  خل الاسم يكون "داخل"؛
  ورني الاسم؛
}
ورني الاسم؛ // الأصل
```

```zyr
سالفة مساحة(الطول، العرض) {
```

## 15. الأخطاء وحدود التنفيذ

| رسالة أو مشكلة | ماذا تفعل؟ |
|---|---|
| الاسم مو معرّف | عرّفه بـ `خل` قبل استخدامه، وتحقق من تهجئته ونطاقه. |
| حط ؛ بنهاية التعليمة | أضف `؛` أو `;` للتعليمة البسيطة. |
| بعد اسم المتغير اكتب «يكون» | الصياغة هي `خل الاسم يكون القيمة؛`. |
| المجموعة ما تقفلت | أضف `}` لكل `{`. |
| ما نقدر نقسم على صفر | غيّر المقسوم عليه. |
| عدد اللفات لازم يكون صحيحاً غير سالب | استخدم عدداً صحيحاً مثل `٣` بدلاً من `-١` أو `٢.٥`. |
| وقفنا التنفيذ لأنه تعدّى الحد | راجع `دام` أو عدد اللفات أو الاستدعاء المتكرر. |
| «رجع» تستخدم داخل سالفة فقط | انقلها إلى جسم تعريف سالفة. |
| سالفة تحتاج معاملات | مرر العدد الصحيح من القيم. |

الحدود الافتراضية هي 100,000 محرف في المصدر، و30,000 خطوة تنفيذ تقريبية، و500 سطر مخرجات، و100 مستوى لاستدعاء السوالف. لكل لفة تكلفة خطوة حتى لو كانت المجموعة فارغة. الحدود ليست مقياس وقت أو نظام حماية متكامل؛ التعابير شديدة التعشيش قد تصل إلى حدود المتصفح. لا تشغّل أكواداً غير موثوقة في سياقات حساسة. المفسر يعمل على خيط الواجهة، وقد يتسبب تحليل مدخلات معينة في بطء مؤقت.

## 16. جدول الكلمات والرموز

| الصياغة | الدور |
|---|---|
| `خل ... يكون ...؛` | تعريف متغير |
| `الاسم يصير ...؛` | تغيير قيمة متغير موجود |
| `ورني ...؛` | عرض قيمة أو قيم |
| `لو ... { ... } غير كذا { ... }` | قرار وفرع بديل اختياري |
| `دام ... { ... }` | تكرار مشروط |
| `لف ... مرات { ... }` | تكرار محسوب مرة واحدة؛ المتغير المحلي `الجولة` |
| `سالفة ...(...) { ... }` | تعريف عملية قابلة للاستدعاء |
| `رجع ...؛` | إعادة قيمة من السالفة |
| `صح`، `غلط`، `فاضي` | قيم جاهزة |
| `و`، `أو`، `مو` | منطق |
| `يساوي`، `أكبر من`، `أقل من` | مقارنة كلامية |
| `+ - * / % == != < > <= >=` | حساب ومقارنة رمزية |
| `؛` أو `;` | إنهاء تعليمة بسيطة |
| `،` أو `,` | الفصل بين القيم أو المعاملات |
| `//` أو `#` | تعليق حتى نهاية السطر |

الكلمات `أكبر`/`اكبر` و`أقل`/`اقل` و`أو`/`او` مقبولة. التشكيل الاختياري في الكلمات المحجوزة يسمح مثلاً بـ `ورّني` و`رجّع`. الإنجليزية ليست صياغة أوامر مدعومة في 0.3. معرفات إنجليزية مثل `score` ما زالت مقبولة كأسماء يختارها المبرمج.

## 17. الانتقال من 0.1

| 0.1 القديمة | 0.2 الجديدة |
|---|---|
| `متغير س = ١؛` | `خل س يكون ١؛` |
| `س = ٢؛` | `س يصير ٢؛` |
| `اطبع(س)؛` | `ورني س؛` |
| `إذا (س > ١) { ... } وإلا { ... }` | `لو س أكبر من ١ { ... } غير كذا { ... }` |
| `طالما (شرط) { ... }` | `دام شرط { ... }` |
| `دالة اسم(ن) { أرجع ن؛ }` | `سالفة اسم(ن) { رجع ن؛ }` |
| `صحيح` / `خطأ` / `فارغ` | `صح` / `غلط` / `فاضي` |

النسخة الجديدة تستخدم مفتاح تخزين محلي مختلفاً حتى لا تمسح كود 0.1 تلقائياً. إن كان الكود القديم موجوداً في **نفس بيانات التطبيق أو نطاق المتصفح** يظهر زر استرجاعه. يحتاج تعديلاً يدوياً؛ لا يوجد محول آلي. نسخ الكود خارج التطبيق مهم قبل الحذف أو مسح البيانات أو تغيير مصدر الاستضافة.

## 18. المعمارية التقنية الحالية

1. `web/index.html` و`style.css` و`app.js`: واجهة المحرر ولوحة النتائج والتخزين المحلي.
2. `web/engine.js`: تحليل رموز ثم بناء شجرة تعليمات ثم تنفيذها في نطاقات مستقلة نسبياً؛ لا تستخدم `eval`.
3. `tests/engine.test.js`: اختبارات العقد الأساسي للتعريف والإسناد والقرار والتكرار والسوالف والأخطاء والحدود.
4. `android/app/.../MainActivity.java`: يستضيف ملفات الواجهة المحلية داخل WebView، دون إعلان إذن إنترنت. يوجد جسر محدود لتغيير اتجاه الشاشة والعودة، دون وصول إلى الملفات أو الشبكات؛ وليس بديلاً عن تدقيق أمني.
5. `android` و`.github/workflows/android.yml`: مصدر التطبيق ومسار بناء Android منفصل.

هذه بنية أولية، وليست نموذج عزل أمني مدققاً أو محرك تنفيذ أصلياً. اختلاف صياغة القواعد عن بايثون لا يعني أن كل أفكار البرمجة التي تستخدمها زيرون جديدة على العالم.

## 19. رؤية المترجم ومحرك التنفيذ

يمكن مستقبلاً تصميم سلسلة: ملف `.zyr` ← تحليل رموز ← تحليل نحو ← فحص أسماء ومعانٍ وأنواع ← تمثيل وسيط ← تحسينات مثبتة الصحة ← تعليمات آلة افتراضية أو توليد أصلي ← ربط المكتبات ← برنامج مخصص للمنصة. ينبغي تثبيت المواصفة ومعانيها واختبار التوافق قبل وعد المستخدم باستقرار طويل الأمد.

قد تسمح آلة افتراضية مستقبلية بتشغيل نفس البرنامج على منصات متعددة، مع إمكان إضافة توليد أصلي لاحقاً إذا بررت القياسات كلفته. بناء APK من برنامج زيرون يتطلب تكامل أدوات أندرويد ودورة الحياة والصلاحيات والتوقيع؛ التطبيق الموجود هو **محرر زيرون نفسه** ولا يؤدي هذا التحويل.

## 20. الأنواع والذاكرة والأخطاء والتزامن مستقبلاً

تقترح الرؤية أنواعاً صحيحة وعشرية ونصوصاً وأحرفاً ومنطقاً ومصفوفات وقوائم وقواميس وكائنات وقيم فارغة ودوال. يجب تحديد أحجام الأعداد والتجاوز والدقة والترميز والمساواة وعمليات التحويل قبل تثبيت السلوك. قد تضاف أصناف وواجهات وأنواع عامة أو فحص أنواع حسب تصميم مجرب لا لمجرد زيادة الصعوبة.

تحتاج إدارة الذاكرة إلى قرار بشأن جامع النفايات أو الملكية أو مزيج، وتحتاج الموارد مثل الملفات إلى تحرير واضح. تتطلب الاستثناءات والتزامن والإلغاء تحديد سلوك السباقات ونقل البيانات. لا تنفذ 0.2 هذه الأنظمة بشكل مستقل، بل تستخدم ذاكرة JavaScript وحدوداً بسيطة للتنفيذ.

## 22. رؤية الألعاب والذكاء الاصطناعي

قد يبدأ محرك الألعاب بنافذة و2D وإدخال وصور وصوت وتصادم بسيط، ثم محرر مشاهد، ثم 3D وإضاءة وتحريك وفيزياء وشبكات بحسب الموارد والاختبارات. العالم المفتوح والألعاب الجماعية تتطلب بنية وفرق تطوير واختبارات على أجهزة متعددة؛ ليست خاصية موجودة بمجرد وجود كلمة «ألعاب» في الخطة.

وفي الذكاء الاصطناعي يمكن البدء بعمليات موترات صحيحة واختبارات مشتقات عددية، ثم نماذج صغيرة وتدريب وتشغيل ومجموعات بيانات، وبعدها خلفيات GPU مدعومة وقياسات دقة وأداء. لا تستطيع النسخة الحالية تدريب شبكة عصبية أو توفير واجهة GPU مستقلة؛ رسم Canvas قد يستفيد من تسريع المتصفح الداخلي بحسب الجهاز.

## 23. التطبيقات والأنظمة

تستهدف الرؤية تطبيقات الهواتف والحواسيب، وأدوات الأنظمة والخوادم، والاتصالات وقواعد البيانات. يتطلب كل هدف تكاملاً مع المنصة، وإدارة دورة الحياة والموارد والصلاحيات والتوقيع والتوزيع. تطبيقات التواصل والمصادقة الحقيقية تحتاج أيضاً بنية خلفية وسياسات خصوصية وأمان، وهي غير متاحة في النموذج الحالي.
