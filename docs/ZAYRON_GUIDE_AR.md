## 1. الفكرة والرؤية

زيرون مشروع طموح للغة برمجة عربية تدعم أيضاً صياغات إنجليزية. الهدف البعيد بناء منظومة يستطيع المطور استخدامها في الألعاب والتطبيقات والأنظمة والذكاء الاصطناعي، بدءاً من كتابة الشيفرة وصولاً إلى بناء البرنامج النهائي. تكمن قيمتها المقترحة في جعل العربية جزءاً أصيلاً من تجربة البرمجة، وليس مجرد ترجمة لواجهة المستخدم.

لا تعني قوة اللغة أن تكون صعبة بلا فائدة؛ القوة الحقيقية تقاس بإمكانية التعبير، وسلامة التنفيذ، والأداء المقاس، وجودة الأدوات، والاستقرار، وسهولة تعلم الأساسيات مع إتاحة ميزات متقدمة للخبراء. لا يمكن الجزم بأن زيرون من أقوى لغات العالم قبل تطويرها واختبارها ومقارنتها بمشاريع حقيقية.

## 2. الوضع الحالي وما هو مخطط فقط

### موجود الآن في 0.1

- واجهة عربية متجاوبة تعمل من ملفات محلية وتضم محرراً، أرقام الأسطر، أمثلة، زر تشغيل ولوحة مخرجات.
- حفظ محتوى المحرر في التخزين المحلي للمتصفح أو WebView حيث يتوفر. قد تمسحه بيانات التطبيق أو إعدادات المتصفح، وليس بديلاً عن النسخ الاحتياطي.
- مفسر تجريبي مكتوب بـ JavaScript يستخدم تحليل الرموز والتحليل النحوي والتنفيذ؛ لا يشغّل النص باستخدام `eval`.
- متغيرات وإعادة إسناد، أعداد ونصوص وقيم منطقية و«فارغ»، حساب ومقارنات، شروط، حلقات، دوال وطباعة.
- أسماء مختارة بالإنجليزية، ورسائل أخطاء عربية، وحدود لخطوات التنفيذ وعدد المخرجات وعمق الدوال.
- تطبيق أندرويد تجريبي يحمل هذه الملفات محلياً ولا يتطلب اتصالاً لتشغيل الأمثلة الأساسية.

### غير موجود الآن

لا يوجد حتى الآن مترجم أصلي مستقل أو ملفات تنفيذية `zexe`، ولا محرك ألعاب أو فيزياء أو رسوم، ولا تدريب ذكاء اصطناعي أو GPU، ولا قوائم أو قواميس أو كائنات، ولا ملفات أو شبكات أو قواعد بيانات أو صلاحيات أو تعدد مهام، ولا مدير حزم أو مشاريع أو مصحح أو إكمال تلقائي. دعم العربية والإنجليزية يقتصر على المفردات الموجودة في المرجع أدناه. كل ما عدا ذلك رؤية مستقبلية يحتاج للتصميم والتنفيذ والاختبار.

## 3. تشغيل الاستوديو والتطبيق

### على أندرويد

1. حمّل `zayron-studio-0.1-debug.apk` من صفحة المشروع أو الملف المرفق.
2. افتحه من تطبيق الملفات على جهاز أندرويد 6.0 أو أحدث. عند أول تثبيت قد يطلب النظام السماح لهذا المصدر بتثبيت التطبيقات؛ افحص المصدر قبل السماح.
3. افتح «زيرون ستوديو». اكتب أو عدّل المثال في حقل المحرر واضغط «تشغيل الكود» لترى النتيجة في المخرجات.
4. استعمل أمثلة التعلم وزر مسح المخرجات. الرجوع يعيدك للصفحة السابقة في التطبيق.

الملف موقّع بمفتاح **تجريبي عام** وليس مفتاح إصدار إنتاجي. لا يستخدم للنشر الآمن أو لحماية تحديثات رسمية. قد يعرض Android أو Play Protect تحذيرات؛ لا تثبّت أي ملف إذا لم تثق بمصدره. لم يُختبر هذا الملف على كل أجهزة أندرويد، وقد تختلف تجربة العرض حسب إصدار WebView. إذا تعارض توقيع تثبيت سابق فقد تحتاج لإزالة النسخة السابقة، وعندها قد تفقد بياناتها المحلية؛ انسخ الكود أولاً.

### على الحاسوب أو المتصفح

من جذر المشروع شغّل:

```sh
python3 -m http.server 8000 --bind 0.0.0.0
```

ثم افتح عنوان الخادم واختر المحرر. عند استخدام استضافة بعيدة، افتح عنوانها العام بدلاً من `localhost` على جهاز آخر. كل التنفيذ الأساسي محلي في المتصفح؛ لا يحتاج خادماً خاصاً للغة. للتأكد من سلامة المفسر شغّل `node tests/engine.test.js`.

### بناء أندرويد من المصدر

افتح مجلد `android` في Android Studio مع JDK 17 وAndroid SDK 35 وGradle 8.9، ثم اختر بناء APK تجريبي. أو شغّل `gradle -p android assembleDebug` من جذر المشروع إذا كانت الأدوات متوفرة. الناتج عادة `android/app/build/outputs/apk/debug/app-debug.apk`. توجد أيضاً مهمة GitHub Actions تبني ملفاً تجريبياً عند تشغيلها أو رفع تغييرات متعلقة بالأندرويد أو الويب، وتضعه في Artifacts؛ تحتاج رفع المشروع إلى GitHub وتفعيل Actions أولاً. توقيع إصدارات الإنتاج يتطلب مفتاحاً خاصاً يملكه الناشر وإجراءات منفصلة.

## 4. تعلم اللغة من الصفر

### أول برنامج

```zyr
// التعليق لا ينفذ
اطبع("أهلاً بالعالم!")؛
```

افتح المحرر، اكتب السطر ثم اضغط تشغيل. ستظهر العبارة في لوحة المخرجات. يمكن إنهاء التعليمات بـ `؛` العربية أو `;` الإنجليزية، ويمكن حذفها في الحالات البسيطة. التعليقات تبدأ بـ `//` أو `#` وتستمر حتى نهاية السطر.

### المتغيرات

المتغير اسم يرتبط بقيمة. أعلن المتغير بكلمة `متغير` وغيّر قيمته لاحقاً دون تكرار الكلمة:

```zyr
متغير الاسم = "سارة"؛
متغير العمر = ٢١؛
العمر = العمر + ١؛
اطبع(الاسم، العمر)؛
```

الأسماء العربية والإنجليزية مدعومة مع الأرقام والشرطة السفلية بعد الحرف الأول. الأسماء حساسة لاختلاف الحروف. يجب تعريف الاسم قبل استخدامه، ولا يمكن تعريف الاسم نفسه مرتين في النطاق نفسه.

### أنواع القيم الحالية

| النوع | مثال | ملاحظات |
|---|---|---|
| عدد | `١٢`، `3.5` | يقبل الأرقام العربية والإنجليزية؛ الفاصل العشري نقطة إنجليزية |
| نص | `"زيرون"` أو `'أهلاً'` | يمكن استخدام `\n` للسطر الجديد |
| منطقي | `صحيح` أو `خطأ` | المقابل الإنجليزي `true` و`false` |
| قيمة فارغة | `فارغ` | المقابل الإنجليزي `null` |
| دالة | تعريف عبر `دالة` | الدوال قابلة للاستدعاء باسمها في النموذج |

الأعداد يستخدمها النموذج كأعداد JavaScript، لذا تخضع لحدود الدقة والقيم العددية المعتادة فيها؛ نظام الأعداد المستهدف لم يُحسم. الأحرف والقوائم والمصفوفات والقواميس والكائنات ليست مدعومة بعد كأنواع مستقلة.

### الحساب والمقارنة

تدعم النسخة `+` و`-` و`*` و`/` و`%`. الجمع يجمع عددين أو نصين فقط، وليس نصاً مع عدد؛ لطباعة الاثنين مررهما منفصلين. تحظر القسمة على صفر. المقارنات هي `==` و`!=` و`<` و`>` و`<=` و`>=`. الأقواس تغيّر ترتيب العمليات. المساواة صارمة ولا تحول الأنواع تلقائياً.

```zyr
متغير السعر = ١٥؛
متغير العدد = ٣؛
اطبع("المجموع:", السعر * العدد)؛
اطبع("قيمة كبيرة؟", السعر > ١٠)؛
```

### الشروط

```zyr
متغير الدرجة = ٨٠؛
إذا (الدرجة >= ٦٠) {
  اطبع("ناجح")؛
} وإلا {
  اطبع("استمر في المحاولة")؛
}
```

`وإلا` اختيارية. كلمات المنطق هي `و` و`أو` و`ليس`، ويمكن استخدام `and` و`or` و`not` أو `&&` و`||` و`!`. في النموذج تُقيّم الشروط بحسب قواعد الصدق في JavaScript؛ يفضل استخدام قيم منطقية صريحة.

### الحلقات

```zyr
متغير رقم = ١؛
طالما (رقم <= ٥) {
  اطبع(رقم)؛
  رقم = رقم + ١؛
}
```

يُعاد تنفيذ الكتلة ما دام الشرط صحيحاً. تأكد من وجود طريقة لتغيير الشرط؛ إذا لم تتوقف الحلقة، يوقفها حد خطوات التنفيذ.

### الدوال

```zyr
دالة مربع(عدد) {
  أرجع عدد * عدد؛
}
اطبع(مربع(٤))؛
```

الدالة تجمع خطوات قابلة لإعادة الاستخدام. المعاملات مفصولة بـ `،` أو `,`، ويجب تمرير العدد المطابق منها. `أرجع` تعيد قيمة من داخل دالة؛ بدونها تعيد الدالة `فارغ`. للمتغيرات نطاقات محلية، وتستطيع الدوال قراءة النطاق المحيط بها. الاستدعاء الذاتي ممكن ضمن حد للعمق.

## 5. مرجع الأوامر والتعبيرات الحالية

| العربية | البديل الإنجليزي | الوظيفة |
|---|---|---|
| `متغير` | `let` | إعلان متغير |
| `إذا` أو `اذا` | `if` | شرط |
| `وإلا` أو `والا` | `else` | الفرع الآخر |
| `طالما` | `while` | تكرار مشروط |
| `دالة` | `fn` أو `function` | تعريف دالة |
| `أرجع` أو `ارجع` | `return` | إعادة قيمة |
| `صحيح` / `خطأ` | `true` / `false` | قيم منطقية |
| `فارغ` | `null` | قيمة فارغة |
| `و` / `أو` / `ليس` | `and` / `or` / `not` | عمليات منطقية |
| `اطبع(...)` | `print(...)` | طباعة قيم مفصولة بمسافة |

الكتل محاطة بـ `{` و`}`، وشروط `إذا` و`طالما` محاطة بـ `(` و`)`. ليس كل أمر إنجليزي ممكناً لمجرد وجود ترجمة له؛ الجدول هو قائمة الكلمات الإنجليزية المدعومة فعلياً.

## 6. أمثلة متدرجة

### رسالة شخصية

```zyr
متغير الاسم = "ليان"؛
اطبع("مرحباً", الاسم، "في زيرون")؛
```

### مجموع الأعداد من واحد إلى عشرة

```zyr
متغير المجموع = ٠؛
متغير رقم = ١؛
طالما (رقم <= ١٠) {
  المجموع = المجموع + رقم؛
  رقم = رقم + ١؛
}
اطبع("المجموع:", المجموع)؛
```

### دالة القيمة الأكبر

```zyr
دالة الأكبر(أ، ب) {
  إذا (أ > ب) { أرجع أ؛ }
  أرجع ب؛
}
اطبع("الأكبر:", الأكبر(٧، ١٢))؛
```

### الشروط المنطقية

```zyr
متغير العمر = ٢٠؛
متغير مسجل = صحيح؛
إذا (العمر >= ١٨ و مسجل) {
  اطبع("الدخول متاح")؛
} وإلا {
  اطبع("الدخول غير متاح")؛
}
```

### استخدام الإنجليزية

```zyr
let number = 4;
fn double(value) { return value * 2; }
print(double(number));
```

## 7. الأخطاء الشائعة وحدود النسخة

- **اسم غير معرّف:** تأكد من كتابة `متغير` قبل الاستعمال ومن تطابق الاسم.
- **المتوقع قيمة أو تعبير:** افحص الأقواس وعلامات الاقتباس وعلامات العمليات.
- **الكتلة غير مغلقة:** أضف `}` لكل `{`.
- **لا يمكن القسمة على صفر:** غيّر المقسوم عليه.
- **تجاوز حد التنفيذ:** راجع شرط الحلقة أو تكرار استدعاء الدوال.
- **تتوقع الدالة عدداً من المعاملات:** مرر العدد المطابق للتعريف.

حدود هذه النسخة الافتراضية: 100,000 محرف في المصدر، و30,000 خطوة تنفيذ تقريبية، و500 سطر مخرجات، و100 مستوى لاستدعاء الدوال. الخطوات ليست مقياساً للوقت. المدخلات الطويلة أو التعابير شديدة التعشيش قد تستهلك الموارد أو تنتج خطأً عاماً. يعمل المفسر في خيط الواجهة وليس ضمن بيئة عزل أمنية متكاملة؛ لا تشغّل شيفرة غير موثوقة في سياقات حساسة. لا توجد معالجة استثناءات على مستوى اللغة حالياً.

## 8. معمارية النموذج التجريبي

1. **الواجهة:** `web/index.html` و`web/style.css` و`web/app.js` تعرض المحرر وتستقبل أوامر المستخدم وتحفظ الكود محلياً.
2. **تحليل الرموز:** يقسم `web/engine.js` النص إلى كلمات وأرقام وعلامات، ويسجل رقم السطر.
3. **التحليل النحوي:** يبني تمثيلاً للشروط والدوال والتعبيرات من الرموز.
4. **التنفيذ:** يزور التمثيل ويدير النطاقات، ويفحص حدود التشغيل ويجمع المخرجات.
5. **الأندرويد:** `MainActivity.java` يستضيف ملفات الويب المحلية داخل WebView. لا يعلن التطبيق إذن الإنترنت ولا يحتوي جسراً عاماً من JavaScript إلى Android.
6. **الاختبارات:** `tests/engine.test.js` يغطي أمثلة وعمليات وأخطاء وحلقات ودوال. النجاح فيها لا يغني عن اختبارات أجهزة أندرويد الفعلية.

هذا مفسر تجريبي خاص بقواعد زيرون، لكنه يعمل فوق JavaScript ومحرك المتصفح. لذلك لا ينبغي تسميته مترجماً أصلياً مستقلاً ولا الادعاء أنه ينتج ملفات تنفيذية من المصدر.

## 9. تصميم اللغة المستهدف

### مبادئ مقترحة

- العربية أولوية، مع صياغات إنجليزية محددة ومتكافئة وتوثيق للاثنتين.
- قواعد واضحة قابلة للتعلم وميزات متقدمة لا تُفرض على المبتدئ.
- أخطاء مفهومة بالعربية مع الموقع والسبب واقتراح الإصلاح عند الإمكان.
- تحديد رسمي للنحو والدلالات وترميز UTF-8 قبل تثبيت التوافق.
- مكتبات وإضافات بإصدارات واضحة وعزل مدروس للصلاحيات.
- قياسات موثقة للأداء واستهلاك الذاكرة بدلاً من وعود غير قابلة للتحقق.

### أنواع البيانات المستقبلية

تخطط الرؤية لأعداد صحيحة وعشرية، نصوص وأحرف، منطق، مصفوفات وقوائم، قواميس وكائنات وقيم فارغة ودوال. قبل التنفيذ يجب حسم أحجام الأعداد وسلوك التجاوز والدقة وترميز الأحرف والمساواة والقيم القابلة للتغيير، وتحديد كيفية تحويل الأنواع. تختلف «القائمة» عن «المصفوفة» المحتملة في التكلفة والتغيير، ولا يصح اعتبارهما منجزتين بمجرد تسميتهما.

### البرمجة الكائنية والأنظمة المتقدمة

قد يشمل التصميم أصنافاً وواجهات وتركيباً ووراثة محكومة، وأنواعاً عامة، وفحصاً ساكناً تدريجياً، ووحدات ومساحات أسماء. تحتاج هذه الخيارات إلى مواصفات وتجارب قبل اعتمادها؛ لا تدعمها النسخة الحالية. من الأفضل تجنب تعقيد اللغة لمجرد الصعوبة: كل ميزة يجب أن تعالج مشكلة واضحة وتملك رسائل أخطاء واختبارات.

## 10. المترجم ومحرك التنفيذ المستهدفان

المسار المتوقع لمترجم كامل: مصدر `.zyr` ← تحليل رموز ← شجرة نحو ← تحليل أسماء وأنواع ومعانٍ ← تمثيل وسيط ← تحسينات مثبتة الصحة ← توليد شيفرة أو تعليمات وسيطة ← ربط مكتبات ← مخرجات قابلة للتنفيذ حسب المنصة. يقتضي ذلك تحديد سلوك كل مرحلة واختبار الأخطاء والتوافق.

يمكن إضافة آلة افتراضية بتنفيذ تعليمات وسيطة لتسهيل الحمل، ثم توليد أصلي أو تحسين أثناء التشغيل إذا بررت القياسات الكلفة. بناء برنامج أندرويد مستقبلاً يتطلب سلسلة أدوات أندرويد والتوقيع وإدارة أذونات المنصة؛ امتداد `zexe` وحده لا يجعل الملف قابلاً للتنفيذ على نظام تشغيل. النموذج الحالي ينفذ مباشرة في المتصفح ولا يوفر تلك المراحل الكاملة.

## 11. إدارة الذاكرة والأخطاء والمهام

إدارة الذاكرة المستقبلية قد تستخدم جامع نفايات أو ملكية وموارد ذات تحرير حتمي أو مزيجاً منهما. يجب مقارنة زمن الاستجابة واستهلاك الذاكرة وسهولة الاستخدام، وتحديد عمر الكائنات والموارد وإغلاق الملفات. الأنموذج الحالي يرث إدارة ذاكرة JavaScript ولا يقدم نظاماً مستقلاً.

يقترح نظام الأخطاء أنواع أخطاء، وأثر استدعاءات، واستثناءات أو نتائج صريحة، وتعليمات تنظيف للموارد. أما تعدد المهام فيحتاج تعريف النموذج المتزامن، وعزل البيانات، والإلغاء، وطريقة التعامل مع السباقات. ليس أي منها منفذاً الآن، وحد التنفيذ الحالي حماية بسيطة من بعض الحلقات فقط.

## 12. المكتبات والمنظومة المستهدفة

- **الأساسيات:** نصوص، مجموعات، وقت، أرقام وتنسيق.
- **الرياضيات:** عمليات عددية وإحصاء وجبر خطي بعد تحديد الدقة.
- **الملفات والأمان:** واجهات موارد وصلاحيات صريحة وتشفير مبني على تنفيذات مدققة.
- **الشبكات وقواعد البيانات:** بروتوكولات واتصالات ومخازن مع معالجة للأخطاء والخصوصية.
- **الواجهات والصوت والرسومات:** مكونات وتخطيط وإدخال وإخراج على المنصات المدعومة.
- **الألعاب والفيزياء والذكاء الاصطناعي:** واجهات متخصصة تستند إلى بنية تحتية مختبرة.
- **المهام والهواتف:** نموذج تزامن وتكامل موثق مع دورة حياة المنصة.

هذه كلها مكتبات مقترحة؛ المتاح حالياً هو الطباعة والعمليات الأساسية فقط. يحتاج كل مشروع مكتبة إلى تحديد منصات الدعم والترخيص والإصدارات والاختبارات وحدود الأمان.

## 13. محرك الألعاب المقترح

الرؤية تشمل مشاهد، كائنات، رسوماً ثنائية وثلاثية الأبعاد، خامات وإضاءة، تحريكاً، تصادمات وفيزياء، صوتاً، خرائط، ذكاء للشخصيات، شبكات متعددة اللاعبين وواجهات ألعاب. التنفيذ الواقعي يبدأ بنموذج 2D صغير: نافذة، حلقة تحديث، صور، إدخال، تصادمات بسيطة وصوت؛ ثم بناء محرر مشاهد وتوثيق وعينات وقياسات على أجهزة مختلفة. عوالم ضخمة و3D والشبكات الآمنة تتطلب فرقاً واختبارات ووقتاً كبيراً. لا يوجد محرك ألعاب في 0.1.

## 14. الذكاء الاصطناعي المقترح

تشمل الرؤية تمثيل المصفوفات متعددة الأبعاد، مشتقات تلقائية، طبقات عصبية، محسّنات، تحميل مجموعات بيانات، تدريب وتشغيل، معالجة نصوص وصور، وتسريع GPU. لبناء مكتبة موثوقة ينبغي أولاً تثبيت صحة العمليات والمشتقات العددية، ثم القياس ومقارنة النتائج بنماذج مرجعية، ثم إضافة الخلفيات الرسومية ومتابعة دعم الأجهزة والذاكرة والترخيص. لا تستطيع النسخة الحالية تدريب نموذج أو الوصول إلى GPU.

## 15. التطبيقات والأنظمة المستهدفة

يمكن مستقبلاً استهداف تطبيقات هاتف وسطح مكتب وخوادم وبرامج شبكات وأدوات ملفات وقواعد بيانات. يتطلب كل هدف تكاملاً مع نظام التشغيل ودورة حياة التطبيق والواجهات وإدارة الاعتماديات والتوقيع والتوزيع والأمان. تطوير تطبيق حسابات أو محادثة حقيقي يتطلب أيضاً خدمة خلفية ومصادقة وإدارة أسرار وسياسة خصوصية. محرر أندرويد المرفق أداة لتجربة اللغة فقط ولا ينشئ هذه المنتجات.

## 17. زيرون ستوديو المستهدف

الاستوديو الحالي حقل نص ومخرجات وأمثلة، وليس بيئة تطوير متكاملة. قد تتضمن الخطة محرراً بتلوين الأكواد، تحليلاً أثناء الكتابة، إكمالاً تلقائياً، تنقلاً بين الملفات، مصححاً ونقاط توقف، طرفية، مدير حزم، محرر واجهات، محرر مشاهد، أدوات مشاريع واختبارات. ينبغي تصميم كل أداة للعمل بلوحة المفاتيح وقارئات الشاشة ودعم الاتجاهين، مع الحفاظ على إمكانية العمل دون خدمات خارجية للوظائف الأساسية.

## 18. الأداء والأمان والجودة

القوة والاستقرار يتطلبان اختبارات وحدة وتكامل وتوافق، اختبارات إدخال عشوائي للمحلل، اختبارات على أجهزة فعلية، قياسات واضحة وملفات أداء قابلة لإعادة الإنتاج، مراجعات أمنية وسياسة كشف ثغرات. تتطلب سرعة التنفيذ مقارنة عادلة لأعباء محددة وبإعدادات موثقة، ولا يوجد في هذا المشروع قياس يثبت تفوقاً على لغات أخرى.

لتوزيع آمن يجب إصدار تطبيقات موقعة بمفتاح إنتاج خاص، وحماية المفاتيح، ونشر بصمات رسمية، وتحديد سياسة تحديث، وتدقيق سلاسل الاعتماديات. تطبيق النسخة التجريبية لا يطلب إذن الإنترنت، لكن هذا وحده لا يضمن الأمان الكامل للمتصفح أو الجهاز.
