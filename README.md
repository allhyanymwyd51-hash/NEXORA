# NEXORA

A complete AI-world mobile game: an Android client written in C++ on raw OpenGL ES, and a
zero-dependency Node 22 backend. Worlds are generated by NEX AI from a text prompt, published,
joined, and played in first person; every currency, pass, chat message and moderation action is
server-authoritative.

- **Client** — `client/` · native C++17, no NDK, no Gradle, no Google/Maven artifacts
- **Server** — `server/` · Node 22, `node:sqlite`, no npm dependencies
- **APK** — `client/build/nexora-1.0.0.apk` (arm64-v8a, minSdk 26, targetSdk 34)

## Running the server

```bash
cd server
npm run owner        # create the owner account (interactive)
node src/index.js    # http://0.0.0.0:8080
```

Environment: `PORT` (default 8080), `HOST`, `DB_PATH`, `NEXORA_SECRET` (session signing key),
`NEXORA_AI_URL` (optional remote LLM; without it NEX AI uses the deterministic local planner).

Day-one endpoints the client calls: `/api/meta`, `/api/auth/{register,login,logout,me}`,
`/api/ai/{generate,jobs/:id,modify,presets}`, `/api/maps{,/mine,/favorites,/:id,/publish,/join,/passes}`,
`/api/play/{heartbeat,leave}`, `/api/shop`, `/api/inventory`, `/api/economy/ledger`,
`/api/me/{profile,settings,passes,notifications}`, `/api/friends`, `/api/chat`, `/api/admin/*`,
and a WebSocket at `/ws` (rooms, presence, chat, voice signalling, invites).

## Building the APK

The toolchain is self-hosted: Zig for the C++/link step, jdk4py + downloaded build-tools for the
Java/dex/aapt2 steps. No NDK, no Android libc — the binary links against generated import stubs
against the platform libraries that ship with Android.

```bash
source /home/user/env.sh      # JAVA_HOME, ANDROID_SDK, BUILD_TOOLS, ZIG
cd client && ZIG=$ZIG ./build.sh
```

Output: `client/build/nexora-1.0.0.apk`, signed v1+v2+v3 with `build/keys/nexora-release.jks`,
native library stored uncompressed and 16 KB page-aligned (Android 15 requirement).

### Rebuilding just the native half

When only `jni/` changed there is no need to redo the Java/dex side (and no JDK is required):

```bash
# zig cc for arm64 against generated import stubs -> build/so/arm64-v8a/libnexora.so
bash tools/build_native.sh
# swap it into the existing APK, re-align, re-sign (pure JS, no apksigner)
NODE_PATH=$(npm root -g) node tools/pack_apk.mjs client/build/nexora-1.0.0.apk /tmp/u.apk \
    client/build/so/arm64-v8a/libnexora.so client/assets
NODE_PATH=$(npm root -g) node tools/sign_apk.mjs /tmp/u.apk out.apk \
    build/keys/nexora.key.pem build/keys/nexora.cert.pem
python3 tools/check_apk.py out.apk      # launch-path pre-flight, no device needed
```

### Art pipeline

The shipped content is real, authored data — not padding, and every file is opened by the engine:

| Asset | Produced by | Used by |
| --- | --- | --- |
| `assets/textures/world/*.png` (1K albedo + normal per material, 2K atlases) | `tools/prep_materials.py` from the scans in `tools/assets_src/` | terrain shader (grass/sand/rock/snow) and building cladding (brick/planks/cobble/metal) |
| `assets/audio/music/*.adp` (9 composed tracks, 90–240 s each) | `tools/gen_music.py` | streamed IMA-ADPCM soundtrack, decoded on demand |
| `assets/audio/*.wav` (46 effects/ambiences) | `server/scripts/gen-audio.js` | gameplay SFX |
| `assets/fonts/Cairo-*.ttf` | SIL OFL | Arabic shaping |

## Tests

```bash
cd server && node --test 'test/*.test.js'   # 30 backend tests
python3 tools/test_assets.py                # codec + material asset tests
python3 tools/check_apk.py client/build/nexora-1.0.0.apk   # launch-path pre-flight
```

30 tests: the full player journey (register → create → NEX AI generate → publish → join →
heartbeat/Miy → social → shop → passes → owner console), the realtime protocol driven over raw
WebSocket framing, client-contract regressions, and the AI edit engine.

## Design rules held throughout

- **Arabic first, RTL native.** Every string exists in Arabic and English; the layout mirrors,
  text is shaped with HarfBuzz-free Arabic joining over Cairo (SIL OFL, bundled).
- **Self-contained content.** No NDK, no third-party engine, no runtime downloads: PNG and
  IMA-ADPCM decoding live in `jni/core` (`png.cpp`, `inflate.cpp`, the ADPCM path in `audio.cpp`),
  the artwork is authored into `tools/assets_src/` and packed by `tools/prep_materials.py`, and the
  soundtrack is composed by `tools/gen_music.py`.
- **No fabricated state.** Empty lists say they are empty, failures say what failed, and no screen
  shows a number the server did not send.

## Layout

```
client/jni/core     engine, GLES renderer, font/shaping, audio, net, ui kit
client/jni/app      router + one translation unit per screen
client/jni/world    world spec loading, terrain, procedural props
client/jni/game     first-person gameplay
server/src/core     db, auth, economy, moderation, realtime
server/src/api      route modules (auth, maps, ai, shop, social, admin)
server/src/ai       deterministic world generator + modification engine
tools/font-preview  host-side renderer to check Arabic shaping without a device
tools/              art/audio pipeline, APK packer + signer, launch-path checks
```

## Pointing the client at a server

The client is built against `http://10.0.2.2:8080` (the emulator's route to the host machine).
On a real phone, open the login screen, tap the **Server** chip under the buttons and type the
machine running the server — `192.168.1.20:8080`, or a full `http://…` / `https://…` URL. The
address is saved with the session and used for both REST and the WebSocket. Start the server with
`HOST=0.0.0.0` so the phone can reach it.

## Honest limits

The APK has been built, signed and verified, and its C++ was compiled per translation unit; the
server has been exercised end to end and by its test suite. It has **not** been installed on a
physical device or emulator in this environment, so on-device rendering, audio and touch latency
are unverified.
